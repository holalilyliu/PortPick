# PortPick 2.0 · MGT6325 Stage 1 校园自提

解压整个文件夹后双击 `index.html`。页面使用繁体中文，金额使用人民币 CNY。也可用同一地址打开现有本机网站。请在整个演示期间使用同一设备、浏览器和网站地址。

## 演示顺序

1. 点顶部「登入演示帳號」，输入一个课堂代号，例如 student-a。相同名称会回到同一演示账号。首次进入需先登入课堂演示账号；此为无密码的演示账号机制，不是安全身份验证。
2. 在「購買門店」选深圳前海店。深圳口岸仅作路线信息。系统按门店和口岸坐标推荐最近口岸，可手动调整。可用中文、英文或分类搜索有库存的商品。选择商品、完整单位份量与分装选项后加入购物袋。
3. 在购物袋里调整份量、数量或分装选项，选择 CityUHK 校园模拟自提点。点「核對費用並結賬」，确认金额，选择微信支付、支付宝、AlipayHK 或银联／银行卡，再点「確認模擬付款並下單」。
4. 成功页显示订单号。「查看訂單進度」直接打开该笔订单。以后可随时从首页顶部的 **My Orders / 我的訂單** 打开任意一笔自己的订单，最新订单排在前面。
5. 演示人员点页脚「課堂演示 · 推進訂單」，选择一笔订单，确认推进一阶段。每次操作后需要重新选单。用户订单页提供只读进度。
6. 到点后，订单详情顶部显示「可以取貨」、校园地点和固定取货码。前两阶段提示「請等候到點通知」。所有进度时间以香港时间显示。
7. 切换到 student-b 可测试账号隔离。重新登录 student-a 查看原订单。演示账号按名称区分，无密码，适用于同一设备轮流演示。

## 费用与配置

商品单价按最小可售单位从采购价分摊、四舍五入至分，再乘以实际购买数量。整单商品小计乘以服务费率后四舍五入到分。分装费按所选外包装单价与外包装份数计算。新商品行默认一份，购物袋中可独立修改。旧购物袋迁移时保留原有包装份数。合计为商品小计、整单服务费、分装费之和。深圳口岸距离不参与 Stage 1 计费。

- 浏览器配置文件为 `catalog.js`。在 `stage1.serviceFeeBasisPoints` 修改服务费率。2000 表示 20%，1500 表示 15%。
- `stage1.minimumHKD` 默认 100，单位为港元。设为 0 可关闭起送门槛。
- `stage1.cnyToHKD` 默认 1.10，表示 1 CNY 换算为 1.10 HKD，属于课堂演示汇率。修改网页配置后刷新。只换算商品小计，四舍五入到港分后比较门槛。付款方式、汇率、港元商品小计和门槛随订单保存。
- 在 `stage1.campuses` 添加校园地点，包含唯一的 `id`、显示名称 `name`、到点时出现的 `location` 和模拟标识 `simulated`。待确认场地在名称和地点中注明「模擬自提點」。
- `catalog.json` 是同一份配置的 JSON 版本。维护时可先编辑它，然后在本文件夹同步生成网页配置：

```sh
python3 -c "from pathlib import Path; p=Path('catalog.json'); Path('catalog.js').write_text('window.PORTPICK_CATALOG = '+p.read_text(encoding='utf-8').strip()+';\n',encoding='utf-8')"
```

新订单保存所选门店、自提点、商品份量及单价、数量、分装选项及单价、费率、全部金额和状态时间。取货码随订单一次生成，到点后显示。修改配置影响之后的报价。

## 保存范围与旧订单

Stage 1 的新订单保存在浏览器 localStorage 中，按演示账号筛选。所选门店的可用示例库存按本浏览器已提交的 Stage 1 订单扣减。刷新会保留当前账号，登出后可用同名账号恢复订单。不同设备、浏览器、文件地址或网站端口拥有各自的存储。浏览器清理站点数据会清除本机演示订单。

旧版 2.0 本地预约按原「测试编号或称呼」匹配演示账号。使用原服务时也可读取原浏览器会话仍能访问的旧预约。1.0 历史订单按原演示用户名对应的用户键匹配。旧订单以原有总额及状态显示，不补算新的 20% 服务费，未知字段显示「未記錄」。没有可核对归属的旧订单保留在原存储中，不展示给其他账号。

`server.py` 和原启动脚本可继续用于提供网页及读取旧版共享预约。Stage 1 新订单使用静态网页的本机存储。团队成员若要轮流推进同一笔订单，需要使用同一浏览器的同一账号。校园自提点、付款和库存均为课堂模拟。

手机首页右上角可切换账号。右下角悬浮购物袋可打开购物袋。商品图沿用项目内 CSS 包装插画，旧单无图时显示占位符。点商品明细中的名称可展开全文。

## 门店地图与到点时间

门店示意图随卡片、星标按钮和口岸下拉框同步更新。星标可用 Tab 聚焦，再按 Enter 或空格选店。离线底图位于 `store-map-base.svg`，可以直接替换。背景文件名、画布尺寸、两店和四个口岸的示意坐标集中在 `maps-config.js`，坐标从左上角起算。若改用新文件名，通过内置服务器打开时也需更新 `server.py` 中的静态文件表和对应 MIME 类型。直线距离由 `engine.js` 的 routes 函数使用 `catalog.js` 中的真实经纬度计算。深圳口岸供路线参考，香港校园自提点在购物袋中选择。

结账可以选「尽快送达」或未来七天的预约时段。配置集中在 `engine.js` 的 `DELIVERY`（10:00–22:00、5 小时准备配送时间、凌晨判定和 30 分钟间隔），全部按 Asia/Hong_Kong 计算。时间是预计商品到校园自提点的课堂演示假设，不是物流承诺。订单保存送达模式、下单时间、时间窗口及 `Asia/Hong_Kong` 时区；历史订单没有此字段时显示「未指定」。


## 最小单位与日期提醒配置

`catalog.js` 是浏览器实际读取的配置，`catalog.json` 保存相同数据，修改后按上方命令同步。

- 每个商品的 `sale.units` 表示一个最小可售单位包含多少原始单位，`sale.label` 是瓶、盒、袋或包等显示单位，`sale.maxQuantity` 是同款的合计限购数量。原有 `packUnits` 和 `price` 继续表示团队采购规格和采购价。所有现有完整瓶、盒、袋均按一个完整单位出售。配置为整箱出售时，令 `sale.units` 等于 `packUnits`，并将标签设为箱。
- `sizes` 用作快捷数量。点击快捷数量后，可继续逐个最小可售单位加减。重新打开商品页编辑已有购物袋行，更新按钮保存编辑结果。
- `stage1.shelfLife.shortDays = 7` 表示预计取货时剩余0–7天的范围。`singleQuantity = 4` 为同款提醒数量，`combinedProducts = 2` 及 `combinedQuantity = 6` 为多款累计门槛。这些是可修改的课堂演示规则。
- 商品 `batch.markedDate` 使用包装标示的 `YYYY-MM-DD` 日期，`batch.id` 保存批次识别，`batch.demo` 标明是否演示数据。日期未知时可以省略该字段或设置为null。只有通常保存时长时，页面显示日期待确认。
- 剩余天数按包装标示日期减去预计自提的香港本地日期计算。购物袋选择时间、改变数量、移除商品和结账改期都会重新判断。普通短保提醒提供调整、保留及符合条件时的其他选择。预计自提晚于标示日期时，需调整商品或自提安排再提交。
- 新订单保存最小单位、购买数量、采购规格、单价、包装份数、金额、批次资料、预计自提日期和本次日期判断。旧订单按原快照展示。

## 课堂演示商品

商品区「課堂演示 · 數量與日期測試」进入七款明确标示的演示商品。配置位于 `shelfLifeDemo`。演示模式采用HKD，每瓶HK$8、采购规格24瓶，门槛HK$0，支持独立提交5瓶HK$48的验收订单。一般目录使用现有CNY计价和HKD100门槛。两种目录的购物袋分别保存，订单沿用现有账号存储。

先在购物袋把预计自提时间选为2026-11-25 10:00，再选「演示飲品・短保」。包装标示日期为2026-11-28，取货剩3天。按加号至4瓶出现提醒，减回3瓶消失。选5瓶并保留数量，加入购物袋，选择CityUHK及模拟付款，提交后可在我的订单看到5瓶、商品HK$40、服务费HK$8、合计HK$48。

「演示零食・短保」按袋计数，配合饮品各选3个可演示累计提醒。「演示飲品・7天邊界」标示2026-12-02，「演示飲品・較長日期」标示2026-12-03，「日期待確認」没有日期，「需調整批次」标示2026-11-24。固定日期需要团队随课堂日期维护，计算会始终使用实际选择的自提日期。
